# Docker и собственный сервер

Веб-сервис — это та же программа, что и [приложение](cli.md), запущенная командой
`sap-bin serve`. Проще всего разместить его с помощью образа контейнера.

## Запуск образа

Образы для amd64 и arm64 лежат в реестре контейнеров GitHub:

```bash
docker run --rm --read-only -p 127.0.0.1:8080:8080 ghcr.io/aerofeev/sap-bin-parser
```

Затем откройте <http://localhost:8080/>. Контейнеру не нужна файловая система с правом записи.

| Тег | |
|---|---|
| `latest` | самый свежий релиз |
| `0.2.0`, `0.2` | конкретный релиз |
| `main` | последнее слияние в `main` |

## Настройки

| Переменная | Флаг | По умолчанию | |
|---|---|---|---|
| `SAPBIN_BASE_PATH` | `--base-path` | (нет) | работать по пути, например `/sap-bin-parser` |
| `SAPBIN_MAX_UPLOAD_MB` | `--max-upload-mb` | 20000 | наибольший размер принимаемой выгрузки |
| `SAPBIN_MAX_CONCURRENCY` | `--max-concurrency` | 4 | одновременных конвертаций; на остальные запросы — ответ 503 с `Retry-After` |
| `SAPBIN_THREADS` | `--threads` | ядра ÷ конвертации | рабочих потоков на одну конвертацию |
| `PORT` | `--port` | 8080 | |
| `SAPBIN_LOG` | | `info` | уровень журнала |

Каждой конвертации нужно около 150 МБ памяти, каким бы большим ни был файл.

## За обратным прокси

В [`deploy/tools.eidox.io/`](../../deploy/tools.eidox.io/) лежит настройка публичного
экземпляра: защищённый compose-файл и готовые конфигурации Caddy и nginx для работы по пути
`/sap-bin-parser/`. Прокси должен пропускать тела запросов и ответов потоком: для nginx это
`proxy_request_buffering off` и `proxy_buffering off`, иначе он сбрасывает загрузки на диск и
хранит то, что сервис специально никогда не хранит. В [`deploy/`](../../deploy/) также есть
обычный compose-файл и конфигурация для Fly.io.

## Другие реестры

В репозитории есть `.gitlab-ci.yml`: сделайте зеркало репозитория в GitLab, и тот же образ
будет публиковаться в реестр контейнеров этого проекта GitLab.

## Собрать образ самостоятельно

```bash
docker build -t sap-bin .
```
